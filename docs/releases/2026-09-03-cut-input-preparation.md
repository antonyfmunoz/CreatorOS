# Bounded native input preparation

## Concrete gap

Multitrack preparation previously used one `Promise.all` over every referenced
private source. Each callback downloaded a file and spawned an unbounded media
probe. One callback rejecting could start parent-folder cleanup while other
callbacks were still writing. The probe buffered unrestricted stdout, did not
drain stderr, and lacked a lifetime bound or cancellation signal.

## Change

- Prepare at most two private sources per native job. Preserve the original
  source positions and accepted source count. Stop admitting new sources after
  the first error/cancellation, drain already-started operations, then reject.
- Forward the existing job cancellation/lease-loss signal through the R2 SDK
  request, response stream and probe. Local copy completion is awaited because
  `copyFile` cannot interrupt an in-flight copy. Other callers retain the optional
  signal's existing no-signal behavior.
- Inspect only codec type, geometry, sample aspect and rotation. A probe has one
  codec thread, a 30-second lifetime and a 1 MiB stdout budget. Stderr is drained
  without exposing source paths or metadata. Timeout, overflow and cancellation
  wait for actual child exit before releasing the operation.
- Media probing allows file/pipe protocols only: an uploaded playlist cannot
  make its probe fetch remote segments. This is **not** a claim that every FFmpeg
  command in the application is comprehensively network-isolated or that local
  filesystem access is sandboxed. Those remain separate native-runtime hardening
  boundaries.

The queue is per job, not a new global fleet or tenant quota. It does not solve
large-file disk capacity, aggregate animation-frame storage, all-provider transfer
deadlines or cloud cold-start latency. No new infrastructure, pricing, account,
storage visibility, credentials or accepted export resolution changes.

## Verification

Tests exercise ordered bounded concurrency, rejection/cancellation drainage,
real stream handle closure, private-bucket targeting, real child-process exit,
stderr flooding, metadata overflow, missing runtimes, actual encoded media
geometry/rotation/audio and a local-server zero-request playlist check.

The first focused run passed 28 tests and failed the 90-degree fixture assertion.
An independent diagnostic compared full and bounded ffprobe output: both saw no
rotation in a file generated by the legacy `rotate=90` metadata command under
FFmpeg 8.1. Both saw exactly 90 degrees when the fixture used `-display_rotation`.
The fixture now verifies actual display metadata independently before checking
the application probe. The expected angle remains 90; no tolerance changed.
Diagnostic receipt: `native-probe-rotation-20260903063624033/receipt.json`.
The corrected focused run passed all 30 tests in five files; no existing render
deadline or pixel tolerance changed.

Full exact-source, protected browser, deployment and production observations must
be recorded separately. Focused synthetic tests alone do not establish production
readiness or competitive parity.

The implementation follows [FFprobe's selected-entry contract](https://ffmpeg.org/ffprobe.html#Main-options)
and the [documented display-rotation input option](https://ffmpeg.org/ffmpeg.html#Video-Options).
The Cloudflare skill informed preserving the existing S3-compatible, streaming
private-object path; no bucket or provider change was made.
