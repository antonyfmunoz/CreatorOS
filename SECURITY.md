# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include customer
data, credentials, private media, or exploit details in a public report.

Until a dedicated security mailbox is published, report vulnerabilities
privately to the repository owner through GitHub's private vulnerability
reporting channel. Include the affected surface, impact, reproduction steps,
and the minimum evidence needed to validate the report.

The operator will acknowledge a complete report as quickly as practical,
triage account takeover, credential exposure, cross-tenant disclosure,
financial inconsistency, and destructive corruption as critical incidents,
and coordinate remediation and disclosure with the reporter.

## Supported version

Only the current production release is supported. Security fixes are deployed
forward and verified against the current migration and critical-journey gates.

## Safe-harbor boundaries

Good-faith research must avoid privacy violations, denial of service, social
engineering, automated spam, destructive actions, accessing data beyond the
minimum necessary to demonstrate an issue, and retaining or publishing user
data. Stop immediately and report if sensitive data is encountered.
